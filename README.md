# 👻 Phantom Trail

> **Experimental prototype — version 0.1.0**
>
> Phantom Trail is under active remediation. It is not a production privacy product, tracker blocker, security scanner, legal-compliance tool, or validated privacy-rating service.

Phantom Trail is a Chrome extension prototype for recording and visualizing **possible web-tracking signals**. It combines request classification, in-page instrumentation, local history, heuristic scoring, optional AI summaries, and an experimental peer-to-peer transport.

Detection results can contain false positives and false negatives. A signal means that the extension observed an API call, request pattern, or known domain match; it does **not** by itself prove that a company collected, retained, shared, or sold personal data.

## Current status

The source currently contains:

- A WXT/Manifest V3 extension with a React popup and six main views.
- A manually maintained catalog of **56 domain entries across five code categories**.
- Eleven in-page instrumentation signal types, including canvas, WebRTC, font, audio, WebGL, storage, mouse, form, device, battery, and sensor activity.
- Local event storage with a 1,000-event cap and scheduled cleanup for events older than 30 days.
- A heuristic A–F score, charts, a live feed, and a graph built from recorded events.
- CSV and JSON exports. The current “PDF” option produces a plain-text report.
- Optional OpenRouter-powered event-summary analysis when a user supplies an API key.
- Experimental trusted-site, coaching, sync, prediction, notification, scheduled-export, and peer-to-peer modules.

See [Project Status](docs/PROJECT_STATUS.md) for the capability-by-capability assessment.

## Important limitations

### Detection and attribution

The current event model does not reliably separate the page being visited from every third-party resource it loads. Some request and API heuristics are broad and can classify ordinary site behavior as tracking. In-page signals are indicators, not confirmed attribution.

### Privacy scores

Grades are generated by a hand-written heuristic. They have not been calibrated against an independent dataset, audited methodology, or reproducible benchmark. Scores should be treated as experimental explanations of recorded signals—not objective ratings of a website.

### AI

The general assistant is incomplete. Some prompts are routed to local analyzers using keywords; other paths ask OpenRouter to summarize recent event counts and domains. It should not be described as a fully context-aware privacy expert.

### Community data

The peer-to-peer layer is experimental. Peer data is self-reported and unauthenticated. Phantom Trail does not currently provide a trustworthy population benchmark, reputation authority, or verified percentile ranking.

### Privacy-tool detection

The extension can inspect the names and enabled state of supported installed extensions when the `management` permission is available. It does not measure how many requests those tools actually blocked and no longer presents calculated effectiveness percentages as measured facts.

### Incomplete modules

Cross-device sync, scheduled reports, automatic trend snapshots, notifications, trusted-site enforcement, email/cloud export delivery, and several coaching workflows are incomplete or not consistently wired into the extension lifecycle.

## Data and privacy disclosure

Phantom Trail currently requests broad extension permissions, including access to all sites, web requests, tabs, downloads, notifications, alarms, storage, and installed-extension metadata.

The prototype stores tracking-event objects locally. Depending on the event source, a stored URL may contain paths, query parameters, or fragments. Exported CSV/JSON files can include those stored URLs.

When AI is used, event data is sanitized before processing and the current OpenRouter prompt is primarily a summary of domains, counts, tracker types, and risk levels. When the experimental peer network is enabled, aggregate privacy fields may be shared with connected peers.

Read [Privacy and Data Disclosure](docs/PRIVACY_POLICY.md) before installing or enabling optional network features.

## Installation

No release should currently be treated as production-ready. Build and load the extension from source:

```bash
git clone https://github.com/YrFnS/Phantom-Trail.git
cd Phantom-Trail
pnpm install
pnpm type-check
pnpm lint
pnpm build
```

Then:

1. Open `chrome://extensions/`.
2. Enable **Developer mode**.
3. Select **Load unpacked**.
4. Choose `.output/chrome-mv3`.

Detailed instructions and disclosures are in [INSTALL.md](INSTALL.md).

## Development commands

```bash
pnpm dev
pnpm build
pnpm zip
pnpm type-check
pnpm lint
pnpm lint:fix

```

The repository does not currently define a CI workflow or a complete automated test command. Passing a local build, lint, or type check is not evidence that runtime behavior or product claims have been validated.

## Remediation roadmap

- **P0 — Truthfulness baseline:** align documentation and metadata, remove fabricated metrics, disclose limitations, and establish a capability matrix.
- **P1 — Detection and attribution:** distinguish page and resource domains, reduce false positives, attach confidence/evidence, and improve deduplication.
- **P2 — Scoring:** replace defaults and raw-request penalties with evidence-based, reproducible scoring and an explicit “unknown” state.
- **P3 — Data protection:** minimize permissions and stored URLs, tighten optional data sharing, and document all data flows.
- **P4 — Feature completion:** finish or remove incomplete sync, reporting, notifications, export, AI, trusted-site, and community workflows.
- **P5 — Evidence:** add CI, browser integration tests, false-positive fixtures, performance measurements, and security/privacy review gates.
